# Bug Report 027: PowerShell Parser Error in Hook Command

**Date:** 2026-05-24
**Scenario:** Environment Setup / Hook Execution
**Status:** Open

---

## 1. Unexpected Token Error (CRITICAL)

### Description
On Windows systems using the Gemini CLI, command hooks fail with a PowerShell parser error. This occurs because the command string generated by `onboarding.py` starts with a quoted path to the Python executable, but lacks the PowerShell call operator (`&`).

### Evidence
```
ℹ Warning: At line:1 char:76
  + ... Workbench\GitHub\std-context-lab\.venv\Scripts\python.exe" -W ignore  ...
  +                                                                ~~
  Unexpected token '-W' in expression or statement.
```

### Root Cause
In `context_pipe/onboarding.py` -> `build_runtime_hook_command()`, the return value is:
`f'"{python_exe}" -W ignore -c "..." wrap'`

When PowerShell encounters a string in double quotes at the start of a line, it treats it as a literal string rather than an executable command, unless it is preceded by the `&` operator.

### Impact on Lab
All Gemini CLI hooks (`BeforeTool`, `AfterTool`, `PreCompress`) are completely broken on Windows in `v0.4.4`.

---

## 2. Recommended Fix
Prepend the `&` operator when the OS is identified as Windows (`nt`).

```python
cmd = f'"{python_exe}" -W ignore ...'
if os.name == "nt":
    return f"& {cmd}"
return cmd
```
